Vision

No single platform today harmonises research data + real-world evidence + multi-omic spatial data + synthetic data into one format with identifier stability, an LLM query layer, and federated learning support.

Tessera Bio is building that platform. This page documents the three data layers that, combined, create something the world hasn't experienced — a biological knowledge platform, not just a dataset platform.

1. Real-World Evidence & Biobanks
Layer 1

What exists today

UK Biobank (500K), FinnGen (500K), All of Us (1M+), Million Veteran Program (650K). 5M+ genomes with linked clinical outcomes, longitudinal data, and imaging.

What nobody has done

Nobody harmonises biobank data with research data. UK Biobank uses its own format. FinnGen uses another. A researcher who wants to combine TCGA RNA-seq with UK Biobank WGS spends weeks reconciling identifiers and formats.

What Tessera Bio will do

Biobank ingest module: downloads from UK Biobank RAP, FinnGen, All of Us Researcher Workbench. Produces standardised dataset cards. Harmonises gene IDs across biobanks. Creates RWE dataset cards with genomics + phenotypes + outcomes + longitudinal timepoints. Drift reports flag retraining needs when biobanks update annotations.

Why this is novel

First platform to produce ML-ready dataset cards from biobank data — the same harmonised, versioned, split, signed output as research data.

Schema extension

rwe: {
  biobank: "UK Biobank" | "FinnGen" | "All of Us",
  access_type: "controlled" | "federated",
  n_participants: 500000,
  genomics: { type: "WGS", coverage: 30, assembly: "GRCh38" },
  phenotypes: ["ICD-10", "blood_biomarkers", "imaging"],
  longitudinal: { timepoints: 5, max_followup_years: 15 },
  outcomes: ["mortality", "cancer_incidence", "cardiovascular"]
}
2. Multi-Omic Spatial & Single-Cell Resolution
Layer 2

What exists today

10x Xenium (sub-cellular RNA), NanoString CosMx (1000-plex RNA + protein), Vizgen MERSCOPE, CODEX (50+ proteins), 10x Multiome (RNA + ATAC), ASAP-seq (RNA + ATAC + protein).

What nobody has done

Nobody integrates spatial RNA + spatial protein + single-cell multi-ome into one harmonised dataset. Each technology has its own format, coordinate system, and normalisation. A researcher with Visium RNA + CODEX protein from the same section must manually align them — different resolutions, different identifiers.

What Tessera Bio will do

Multi-omic spatial harmonisation: ingest Visium, CosMx, MERSCOPE, CODEX. Align spatial coordinates across modalities (same tissue, different tech → same coordinate frame). Harmonise gene IDs (Ensembl) + protein IDs (UniProt) in one dataset card. Split by tissue region (not donor) — tests spatial generalisation. Output: one Parquet with RNA + protein + coordinates + segmentation.

Why this is novel

First platform to produce a single harmonised multi-omic spatial dataset card — RNA + protein + spatial coordinates in one file, with unified identifiers.

Schema extension

spatial_multiomic: {
  modalities: ["RNA (Visium)", "Protein (CODEX)", "ATAC (ASAP-seq)"],
  coordinate_system: "tissue_section",
  resolution_um: 0.5,
  alignment: { reference: "H&E", transform: "affine" },
  cell_segmentation: true,
  n_cells: 50000, n_genes: 20000, n_proteins: 50
}
3. Synthetic / Generative Data Layer
Layer 3

What exists today

Diffusion models (scDesign3, CellDiff) generate synthetic single-cell profiles. GANs (scGAN) generate trajectories. LLMs (ESM-2) generate protein sequences. None integrated into a dataset platform.

What nobody has done

Synthetic data is always ad-hoc — generated for a specific experiment, used once, discarded. No concept of a 'synthetic dataset card' that is versioned, signed, validated, and available alongside real datasets.

What Tessera Bio will do

Synthetic data as a first-class asset. Generate synthetic RNA-seq, single-cell, or spatial data matching a real cohort. Dataset card with data_provenance.type: 'synthetic' — including generator, training data, validation metrics (FID, nearest-neighbour distance). Available in the catalogue with a 'Synthetic' badge. Augmentation mode: 500 real + 500 synthetic = 1000-sample dataset. Leakage control: synthetic generated from real data can leak donor info if the generator memorises.

Why this is novel

First platform to treat synthetic data as a managed, versioned, signed dataset type — with provenance tracking and leakage control. Not ad-hoc generation; a catalogue asset.

Schema extension

synthetic_generation: {
  generator: "scDesign3" | "Tessera Diffusion v0.1",
  trained_on: "tessera.rnaseq.v0.1.gtex-breast.ensembl-v110",
  validation: { fid_score: 0.034, nn_distance: 0.21 },
  real_data_fraction: 0.5,
  n_synthetic_samples: 500
}

What happens when you combine all three

LLM query across all data types

'Show me patients in UK Biobank with TP53 mutations who also have Visium spatial data available' — impossible today, natural-language with Tessera.

Identifier drift across all sources

When Ensembl v111 releases: '3,017 models need retraining across GEO + UK Biobank + Visium + synthetic.' Nobody reports drift across research + clinical + spatial.

Federated learning across biobanks

UK Biobank data stays in UK. All of Us stays at NIH. Tessera runs locally, only the dataset card is shared. The LLM queries across federated cards without seeing raw data.

Synthetic data for gaps

Rare disease with only 50 real samples? Tessera generates 500 synthetic samples matching the distribution. Dataset card marks them as synthetic with full provenance.

One schema, all data types

Research (GEO), clinical (UK Biobank), spatial (Visium + CODEX), synthetic (diffusion) — all in the same dataset card format. Versioned, signed, validated.

Biological knowledge platform

Not a dataset platform. Not a pipeline runner. A knowledge platform that harmonises, versions, and queries across all biological data — real and synthetic, research and clinical, bulk and spatial.

What this is — and what it isn't

What it is

  • A unified data layer across research, clinical, spatial, and synthetic
  • Versioned, signed dataset cards for every data type
  • An LLM query layer that works across all data types
  • Federated learning without centralising clinical data
  • Synthetic data as a managed, provenance-tracked asset

What it isn't

  • A replacement for GEO, UK Biobank, or 10x Genomics
  • A pipeline runner (we sit above Nextflow/Terra)
  • A foundation model (we provide fine-tuning data for them)
  • A clinical decision support tool (we provide data, not diagnoses)
  • A guarantee that synthetic data is always safe (provenance tracking, not safety guarantees)

Tessera Bio is not a dataset platform.
It's a biological knowledge platform — the first to harmonise research, clinical, spatial, and synthetic data into one versioned, queryable, federated layer.

This is what the world hasn't seen. This is what we're building.
