Data Evolution

Public portals (GEO, DepMap, Ensembl) provide a massive foundation. But they represent historical, publication-filtered, format-fragmented data. The lag between data generation and data availability is 6-18 months. Negative results and exploratory data are lost. Half the records have incomplete metadata.

If Tessera Bio only ingests from public registries, we'll always be downstream of the data — catching up to what was published 6-18 months ago. To make the platform indispensable for a decade, we must capture the next frontiers of biological data. This page documents what's coming and how Tessera's architecture is designed to absorb it — without code rewrites.

1. Spatial Transcriptomics
Tessera v0.22025-2027
Learn more

What's happening

10x Visium, NanoString CosMx, Vizgen MERSCOPE produce spatially-resolved gene expression. By 2027, sub-cellular spatial will be routine.

Why current registries don't cover it

GEO has no spatial filter, no standardised metadata. Each platform has its own format. Spatial data has different leakage patterns (tissue region, not donor).

What Tessera Bio will do

Spatial ingest pipeline (Visium .h5, CosMx .csv, MERSCOPE .parquet). Spatial coordinates in the dataset card. Split by tissue region. Normalise across platforms.

Schema extension

cohort_definition.spatial: { platform, resolution, coordinate_system }
2. Long-Read Sequencing
Tessera v0.32025-2028
Learn more

What's happening

Oxford Nanopore PromethION: >100kb reads, <24h turnaround. PacBio HiFi: >99.9% accuracy. By 2028, short-read will be the minority modality.

Why current registries don't cover it

Long reads capture structural variants, full-length isoforms, and epigenetic modifications (5mC, 6mA) that short reads miss. T2T-CHM13 assembly adds ~200Mb of new regions.

What Tessera Bio will do

Long-read alignment (minimap2). Isoform-level quantification (flair, StringTie2). T2T-CHM13 as alternative pinned assembly. Drift reports handle assembly changes, not just release changes.

Schema extension

reference_versions.assembly: "T2T-CHM13" | "GRCh38" | pinned
3. CRISPR Screens (Perturb-seq)
Tessera v0.32025-2028
Learn more

What's happening

Perturb-seq and CROP-seq combine gene perturbation with single-cell readout. 'What happens to every cell when you knock out gene X' at transcriptome scale.

Why current registries don't cover it

This is causal data, not observational. ML models trained on CRISPR data learn causal relationships — 'knocking out gene X causes phenotype Y' — not just correlations.

What Tessera Bio will do

Perturb-seq ingest pipeline (guide RNA × cell × gene matrix). New split strategy: 'held-out perturbations' (train on guides for genes 1-1000, test on genes 1001-1100). Tests generalisation to unseen perturbations.

Schema extension

perturbation: { type: "CRISPR-KO", guide_library: "Brunello", n_guides: 77441 }
4. Federated Learning Across Institutions
Tessera v0.32026-2029
Learn more

What's happening

Hospitals and pharma have vast genomics data that will never be in public registries — HIPAA, GDPR, institutional governance. Federated learning trains on this data without centralising it.

Why current registries don't cover it

Tessera becomes the interoperability layer: each institution runs the pipeline locally, produces a standardised dataset card, and only the card (not the matrix) is federated. The cards are the metadata; the matrices stay local.

What Tessera Bio will do

Tessera Federated mode: pipeline runs locally, produces standardised card, only card is shared. Central registry of dataset cards (which institutions have which cohorts, under what licences, with what quality). Drift report reconciles across institutions using different Ensembl releases.

Schema extension

federation: { institution_id, data_residency, access_policy }
5. Foundation Models for Biology
Tessera v0.22025-2028
Learn more

What's happening

ESM-2, AlphaFold2, Geneformer, Nucleotide Transformer, scGPT pre-train on massive biological datasets. By 2028, foundation models will outperform task-specific models on most genomics tasks.

Why current registries don't cover it

If the foundation model already 'knows' the biology, the value of a single new dataset decreases. But the value of clean, well-split, leakage-controlled fine-tuning data increases — because fine-tuning on garbage degrades a good foundation model.

What Tessera Bio will do

Position ML-ready datasets as fine-tuning data for foundation models, not training data for from-scratch models. Dataset card includes 'foundation model compatibility' section. Hugging Face integration: load_dataset('tessera/gtex-breast-v0.1').

Schema extension

foundation_model_compat: { models: ["ESM-2", "Geneformer"], input_format, fine_tuning_protocol }
6. Liquid Biopsy & cfDNA
Tessera v1.02027-2030
Learn more

What's happening

Cell-free DNA sequencing from blood is routine for cancer monitoring. Guardant, Foundation Medicine, Grail produce clinical-grade genomic data at 100x GEO's volume.

Why current registries don't cover it

Clinical data has different requirements — traceable to a patient, longitudinal samples, treatment response metadata. Tessera becomes the bridge between clinical and research genomics.

What Tessera Bio will do

Controlled-access tier (dbGaP auth). Clinical metadata schema: patient_id (hashed), treatment_status, timepoint, response. Longitudinal split strategy: 'held-out timepoints' (train on baseline, test on treatment response).

Schema extension

clinical: { patient_id_hash, treatment_status, timepoint, response }
7. AI-Generated Biological Data
Tessera v1.0+2027-2030
Learn more

What's happening

Diffusion models generate synthetic gene expression profiles statistically indistinguishable from real data. By 2028, augmenting real data with synthetic for rare conditions will be routine.

Why current registries don't cover it

Synthetic data can augment real data for rare diseases or underrepresented populations. But models trained on synthetic data may learn generator artifacts, not real biology. Provenance tracking becomes critical.

What Tessera Bio will do

data_provenance.type field: real | simulated | augmented | synthetic. If synthetic: generator model, training data, validation metrics (FID, nearest-neighbour distance). Leakage control: synthetic data generated from real data can leak real donor information if the generator memorises.

Schema extension

data_provenance: { type: "real" | "synthetic", generator, validation_metrics }
8. Quantum Molecular Simulation
Future2032-2035
Learn more

What's happening

Quantum computers approaching scale for molecular simulation. By 2032-2035, quantum-computed protein folding and molecular dynamics may supplement AlphaFold.

Why current registries don't cover it

If quantum-computed structures become a new data modality, Tessera needs to ingest them as standardised structure files (PDB, mmCIF). The identifier-drift problem extends to structural databases (PDB, AlphaFold DB) which also have version drift.

What Tessera Bio will do

Structure data ingest pipeline (PDB, AlphaFold DB entries). Pin to specific releases. Drift-report when new structures are computed. The architecture is designed to absorb new modalities — the JSON Schema versioning + content-first architecture means adding structure data is a schema extension, not a platform rewrite.

Schema extension

structure: { pdb_id, alphafold_id, resolution, method }

Near future (2026-2028)

  • Spatial transcriptomics routine

  • Tessera Bio v0.2-v0.3

Future (2028-2032)

  • Federated multi-institutional ML
  • Liquid biopsy clinical integration
  • AI-generated biological data
  • Tessera Bio v1.0+

Horizon (2032-2035)

  • Quantum molecular simulation
  • Real-time biological data streams
  • Tessera Bio as interoperability layer

What we don't know yet

  • Quantum computing may or may not produce useful molecular simulation by 2035. We're watching, not betting on it.
  • Synthetic data could augment real data — or it could introduce systematic biases that degrade model performance. The data_provenance field is designed to track this, but the validation methods are still emerging.
  • Federated learning at scale across hospitals requires legal frameworks (DPA, BAA) that don't fully exist yet. The technical architecture is ready; the governance is not.
  • Foundation model compatibility — we don't yet know which foundation models will dominate. The schema supports any model, but the fine-tuning protocols will need to adapt as the field evolves.
  • New data modalities we can't predict — the architecture (JSON Schema versioning + content-first + pipeline adapter) is designed to absorb unknown future data types. Adding a new modality is a schema extension + a new ingest module, not a platform rewrite.

Why the architecture absorbs all of this

Content-first

Adding a new data type = edit a JSON file + add a new content manifest. No code changes to the web app.

Schema versioning

New modality = publish dataset-card v0.2.json with new fields. Downstream users pin to v0.1 until they're ready.

Pipeline adapter

New data type = add a new YAML template + validate against the schema. The adapter copies it to content/ and the site picks it up.

Identifier drift

New reference assembly (T2T-CHM13) or new database (PDB, AlphaFold DB) = new drift report. Same pattern, new data source.

This is a 10-year platform, not a 1-year product. The schema and architecture are designed to absorb new data modalities as they emerge — without code rewrites, without platform migrations, without vendor lock-in.
