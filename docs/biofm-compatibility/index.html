BioFM Compatibility

Tessera sits at the data layer beneath Bio foundation model (BioFM) frameworks. Helical (helical.bio) and any other BioFM consumer runs on top of Tessera-pinned data; Tessera does not run BioFMs in-platform. The Tessera release hash pins what the BioFM was fine-tuned on; the audit PDF renders the data provenance for an IND filing.

The substrate relationship, in one diagram

Layer 1 — Data

Tessera Bio

Hash-pinned, leakage-controlled, drift-aware training data. Release hash + audit PDF. Schema v0.4 adds biofm_compatibility as a metadata field.

Tessera does NOT run BioFMs.

Layer 2 — Inference

Helical (or any BioFM framework)

Orchestrates 11+ BioFMs behind a unified Python interface. Runs in-silico perturbation experiments for target ID. 4× over DESeq2 baseline on OpenTargets recovery@100 across 11+ indications.

Helical does NOT pin the data.

Layer 3 — Output (planned v0.5)

Helical outputs → Tessera artefact

Helical target rankings and perturbation predictions come back into Tessera as a new biofm_output artefact type. The Helical model version is recorded alongside Ensembl/UniProt releases — making the Helical run itself reproducible via the Tessera audit trail.

Gated on first pilot partner asking for it.

Why Tessera deliberately does not run BioFMs in-platform

Category, not feature.

Helical is the leading BioFM orchestration framework. Adding a perturbation engine to Tessera puts us in feature-parity with Helical on Helical's home turf. The substrate play says: let Helical be the inference layer.

Stochastic outputs break the wedge.

BioFMs are stochastic (diffusion, sampling). Same input, different seed → different structure. The Tessera release hash is a cryptographic commitment to specific bytes; running inference in-platform would break that contract.

Operating cost.

BioFM inference needs GPUs (A100/H100). Embedding inference in Tessera would mean operating GPU capacity, queues, retry logic, and cost ceilings — the operational burden of being an inference company, not a data substrate.

The right pattern for any BioFM integration: Helical (or any framework) consumes Tessera data; the outputs come back as a pinned artefact; the wedge stays the wedge. This is the same substrate play we apply to cloud labs (v0.4 roadmap), AlphaFold 3, and Co-Scientist.
