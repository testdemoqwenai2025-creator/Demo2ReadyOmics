v0.4 — BioFM compatibility + closed-loop lab integration (active-learning substrate)

Planned

v0.5 — Helical adapter + biofm_run_record + benchmark_result + scale

Q2 2027

Planned
  • tessera.export.to_helical — convert a Tessera release bundle into a Helical-ready input object (gated on pilot demand)
  • New artefact type: biofm_run_record — hash-pinned bundle of (BioFM model version, Tessera release hash consumed, hyperparameters, output predictions, evaluation metrics). Any Helical run that consumes Tessera data automatically gets a Tessera audit trail. Helical doesn't need to change anything.
  • New artefact type: benchmark_result — hash-pinned record of (dataset, BioFM version, benchmark, score, top-N predictions) so the 4× DESeq2 number becomes verifiable, not marketing. A benchmark_result is a specialisation of biofm_run_record.
  • Helical model version recorded alongside Ensembl/UniProt releases in the dataset card — making the Helical run itself reproducible via the Tessera audit trail
  • Controlled-access tier (GTEx, TCGA)
  • LLM-native query layer
  • On-prem deployment
  • CRO / diagnostic partnerships
  • SOC 2 Type 1 preparation
  • API + SDK (Python + R)
  • Community Discord
