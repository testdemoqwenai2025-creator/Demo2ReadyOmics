Single-cell RNA-seq (v0.3)

Single-cell ML's most common silent failure is donor cells leaking across train and test. v0.3 makes this structurally impossible — the held_out_donors_cells split strategy keeps every cell from a donor in the same split, and the audit trail PDF shows exactly which donors went where.

What's real vs. what's scaffold

Honesty matters more than completeness. Here is exactly what is shipped today and what is still placeholder.

Real today

  • • Schema v0.3 with single-cell fields (cell metadata, chemistry pin, taxonomy pin, per-cell QC)
  • • held_out_donors_cells and held_out_donors_timepoints split strategies in splits.py
  • • 4 new unit tests verifying donor-level leakage control (20 tests total pass)
  • • Real release hash for the scaffold bundle: tessera-release:0f7f40eed2cf
  • • Audit trail PDF generation works against the scaffold bundle
  • • /single-cell page, /roadmap, /changelog all updated

Still scaffold

  • • The matrix file at modalities/single-cell-rna-seq.h5ad contains 294 bytes of stub data, not 184,612 cells × 19,742 genes
  • • ingest.single_cell module is planned for v0.3.1 — currently the scaffold bytes are produced by a hand-written script
  • • CellTypist v1.5 has not actually been run on this data — the cell_type_counts are plausible-shape placeholders
  • • The Deng et al. 2024 accession is a placeholder; the real accession needs to be downloaded and re-processed
  • • None of this requires code change. Re-running the pipeline against real CAR-T data replaces the scaffold with real artefacts and produces a new release hash.

The canonical single-cell test

This is the test that prevents the #1 silent failure in single-cell ML. It runs as part of the Tessera unit test suite on every code change. The test verifies that every cell from a donor lives in exactly one split — no half-and-half.

# tests/test_splits.py
def test_held_out_donors_cells_keeps_all_cells_from_one_donor_together():
"""Stronger property: every cell from donor D0000 must be in
exactly one split — no half-and-half."""
samples = _single_cell_samples() # 5 donors × 1000 cells each
splits = generate_splits(
samples=samples,
strategy="held_out_donors_cells",
test_fraction=0.2,
val_fraction=0.2,
seed=42,
)
donor_splits: dict[str, set[str]] =
for split_name, cell_list in splits.items():
for cell in cell_list:
donor = cell["donor_id"]
donor_splits.setdefault(donor, set()).add(split_name)
for donor, split_names in donor_splits.items():
assert len(split_names) == 1, (
f"donor {donor} leaked into {len(split_names)} splits"
)

Four leakage failures v0.3 structurally prevents

Donor cells split across train and test

Common in published single-cell ML papers

Cause. Naive random splitting treats each cell as an independent sample. Cells from the same donor end up in both train and test, inflating test metrics by 5-25% depending on cohort heterogeneity.

Tessera fix. held_out_donors_cells strategy — all cells from a donor go to one split. Verified by the unit test test_held_out_donors_cells_keeps_all_cells_from_one_donor_together.

Donor timepoints treated as independent

Common in longitudinal single-cell studies

Cause. A donor's day-0 baseline and day-28 post-treatment cells end up in different splits. Model appears to generalise across time but is actually recognising donor-of-origin signals.

Tessera fix. held_out_donors_timepoints strategy — donor-timepoint pairs stay together. Test set tests generalisation to unseen donors, not unseen timepoints of seen donors.

Cell type label drift across taxonomies

Universal — every paper uses a different taxonomy

Cause. Authors use CellTypist v1.4 in one paper, Azimuth v0.4 in another, manual annotation in a third. 'CD4 T cells' from paper A is not the same set as 'CD4 T cells' from paper B. Models trained on one set silently misclassify cells from the other.

Tessera fix. Cell-type taxonomy is pinned in single_cell_metadata.cell_type_taxonomy. Re-running with a different taxonomy produces a new release hash. Cross-paper comparison is now reproducible.

10x chemistry batch effects

Universal — chemistry differences silently corrupt cross-cohort comparisons

Cause. 10x-v2 has different gene coverage and noise floor than 10x-v3 or 10x-v3.1. Models trained on v2 data, applied to v3 data, silently degrade. Most papers do not report chemistry.

Tessera fix. single_cell_metadata.chemistry is pinned. Cards with different chemistries cannot be naively merged — the cross_modal_join logic explicitly reports incompatible chemistries.

Why single-cell is v0.3, not v0.4

Single-cell was promoted from v0.4 to v0.3 because every prospect in the validation toolkit's 30-name list works with single-cell data, not bulk RNA-seq. Insilico's PandaOmics, Cradle's protein engineering, Sanger's variant effect prediction — all three use single-cell as the unit of analysis. Shipping v0.3 first means the co-development pilot channel is unblocked before the closed-loop lab integration (v0.4) starts. The order matters: the modality the partner uses has to be in the schema before the partner can evaluate the platform.
