Changelog

v0.4.02026-09-18

BioFM compatibility — substrate relationship with Helical and other Bio foundation model frameworks

  • New optional schema field biofm_compatibility — Tessera cards declare which BioFMs (Geneformer, scGPT, Tahoe-x1, ESM-2, etc.) are known to consume a dataset's modality, the input format, and perturbation support. Tessera does NOT run any BioFM — this is metadata only.
  • New /biofm-compatibility page documenting the substrate relationship: Tessera = data layer, Helical = inference layer, Helical outputs come back as a hash-pinned artefact type (planned for v0.5)
  • Populated biofm_compatibility on the v0.2 CPTAC-BRCA card (Geneformer + ESM-2) and the v0.3 CAR-T card (Geneformer + scGPT + Tahoe-x1 + Cell2Sentence-Scale)
  • Updated /data-evolution Foundation Models frontier with Helical as the substrate-compatible downstream consumer — Tessera sits beneath Helical; Helical runs on top; we deliberately don't compete on inference
  • Dataset detail page (/datasets/[id]) now renders the biofm_compatibility section with per-model badges for perturbation support and modality match (exact / compatible / approximate)
  • New schema file: public/schema/dataset-card.v0.4-extension.json (additive over v0.3; v0.2/v0.3 cards validate unchanged)
  • Roadmap: v0.4 (BioFM compatibility + closed-loop labs) and v0.5 (tessera.export.to_helical + benchmark_result artefact + scale) — both with explicit substrate-consistent deliverables
v0.3.02026-09-18

Single-cell RNA-seq as a first-class modality

  • New schema/dataset-card.v0.3.json — additive over v0.2 with single_cell_metadata, cell-level QC, chemistry pin, and cell-type taxonomy pin
  • splits.py: new held_out_donors_cells strategy (canonical for single-cell) + held_out_donors_timepoints (longitudinal single-cell)
  • harmonise.py: new Modality.SINGLE_CELL_RNA_SEQ + SingleCellRelease class pinning Ensembl release + CellTypist taxonomy + 10x chemistry together
  • 4 new unit tests verifying donor-level leakage control — every cell from a donor lives in exactly one split, never split across train and test (20 tests total pass)
  • New CAR-T responder scaffold demo card — 24 donors, 184,612 cells, real release hash tessera-release:0f7f40eed2cf, explicit scaffold notice in the card YAML
  • New /single-cell page — honest about what's real (schema, splits, tests, release hash) vs scaffold (matrix bytes, ingest module)
  • Schema v0.3 marked as latest; v0.1 and v0.2 cards still validate unchanged
  • datasets-index + content loader + datasets.ts extended for the new card; /datasets catalogue now lists 5 datasets
v0.2.72026-09-18

21 CFR Part 11 audit trail PDF generator (Pillar 1, compliance substrate)

  • New pipeline module tessera.audit — converts any release bundle into a regulator-ready PDF
  • New /audit page on the demo site with the live CPTAC-BRCA Part 11 audit PDF (8 pages, 193 KB, downloadable)
  • PDF includes: exec summary, release identification, data provenance chain, identifier drift status, leakage controls, batch effects, cryptographic signatures, reproducibility statement (tessera checkout command), and three-block sign-off (Data Engineering, QA, Regulatory Affairs)
  • Page 8 of the PDF includes explicit mapping to 21 CFR Part 11 sections 11.10(a), 11.10(c), 11.10(d), 11.50, 11.70
  • Generator script: scripts/generate_audit_pdf.py (ReportLab body + Playwright HTML cover + pypdf merge)
  • Cover normalised to match body page dimensions exactly (no page-size inconsistency)
  • Home page leads with two featured cards: signature capability + audit trail
v0.2.62026-09-18

Reproducible Release as a Commit — the signature capability ships

  • New pipeline module tessera.release — content-addressable bundle with SHA-256 release hash (short form = 12 hex chars, like a git commit)
  • New CLI sub-commands: tessera release + tessera checkout --expected-hash
  • 11 unit tests proving same-input → same-hash and byte-identical checkout
  • New /release page on the demo site explaining the wedge with the live CPTAC v0.2 release hash
  • CPTAC-BRCA multi-omic demo dataset card now carries a real, verifiable release_hash
