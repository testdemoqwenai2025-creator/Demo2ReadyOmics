21 CFR Part 11 Audit Trail

The wedge (release hash) is a cryptographic artefact. The instant a pharma procurement team sees it, they ask: "Can you produce a 21 CFR Part 11 audit trail from this for our IND filing?" If we answer "no", the deal stalls for 6–12 months. This page is the answer "yes, automatically, for every release."

21 CFR Part 11 Audit Trail Report

Generated from CPTAC-BRCA v0.2 release · 8 pages · 193 KB · PDF/A-compatible

PART 11 READY

What this PDF proves

The PDF establishes the cryptographic chain of custody between the Tessera release bundle identified by tessera-release:c254cad07f3d and any model trained on it. It is generated automatically from the bundle — every number in the PDF is read from the hash-pinned artefacts, not hand-written. A reviewer can reproduce the exact byte-for-byte bundle using the tessera checkout command on page 8 of the PDF.

How the wedge maps to 21 CFR Part 11

Each row of this table is a specific section of 21 CFR Part 11 and the exact mechanism by which Tessera Bio addresses it. The same mapping appears on page 8 of the generated PDF, signed by the release hash.

Part 11RequirementHow Tessera addresses it
11.10(a)Validation of systemsTessera's release/checkout pipeline is validated by 11 automated unit tests covering determinism, tamper detection, byte-identical checkout, short-form hash matching, and missing-artefact failure.
11.10(c)Record retention and protectionEvery release bundle is a self-contained directory whose integrity is verifiable offline using only the release hash; no external state is required for verification.
11.10(d)Limit system accessProduction deployments use Sigstore / cosign for signing keys; ABAC layer (Track D2) controls per-team access to release bundles in shared deployments.
11.50Computer-generated, time-stamped audit trailsEvery release carries a release_date, signing_key identifier, and per-artefact SHA-256; the manifest is the audit trail.
11.70Signature / record linkingThe release hash cryptographically binds the signature to the signed records; any change to a record changes the hash and invalidates the signature.

Why this is the highest-leverage piece to ship next

It converts the wedge into a commercial asset

The release hash on its own is a cryptographic artefact. The audit PDF is what a regulatory affairs team can actually file. Without this conversion, the wedge is interesting but not actionable.

It unblocks the first pharma R&D deal

Every pharma procurement team asks "do you have a Part 11 story?" in week 1 of vendor review. With this PDF we answer "yes, automatically, here is a sample." Without it we answer "eventually" and lose the quarter.

It costs us a day, not a quarter

The generator is ~700 lines of Python using ReportLab + Playwright. It reads artefacts we already produce. No new pipeline, no new schema, no new infrastructure. The cost of not having it is the deal stall.

What comes next: ABAC and the DPA template (Pillar 2)

The audit trail (Pillar 1) answers "can you produce a Part 11 document?" The next question procurement asks is "can Team A and Team B use this on the same deployment without seeing each other's data?" That's Pillar 2 — attribute-based access control (ABAC) plus a DPA template. It's a 2-week engineering lift once Pillar 1 is in market. Co-development pilot outreach (Pillar 3) starts after both have shipped.
